## 2. File Naming Convention

```
{embodiment}_{task}_{view}_{trial:02d}.{ext}
```

Examples:
- `fr3_pour_to_fill_line_hero_01.jpg`
- `ur10e_sponge_wash_overhead_03.mp4`
- `bimanual_handoff_plug_side_02.jpg`

### View codes

| Code | Description |
|------|-------------|
| `hero` | Best single frame showing task mid-execution (primary paper figure) |
| `overhead` | Top-down / birdview camera (Azure Kinect birdview or ZED Mini) |
| `side` | Sideview camera (Azure Kinect sideview or tripod) |
| `wrist` | Wrist-mounted RealSense D435I view |
| `wrist_left` | Left arm wrist cam (bimanual only) |
| `wrist_right` | Right arm wrist cam (bimanual only) |
| `external` | ZED Mini center tripod view (bimanual only) |
| `close` | Close-up detail shot (e.g., gripper on object, pour stream) |
| `annotated` | Image with SAM3 detection overlays / BT annotation |
| `sequence` | Multi-frame strip showing task progression |
| `setup` | Hardware / workspace photo |
| `full` | Full-trial video, all views tiled |

### Extensions

| Ext | Use |
|-----|-----|
| `.jpg` | Stills, 300 DPI minimum for print |
| `.png` | Stills with transparency or SAM3 overlays |
| `.mp4` | Videos, H.264, 30 fps |

## 3. Resolution Requirements

### Stills (for paper figures)

| Purpose | Minimum resolution | Format |
|---------|-------------------|--------|
| Full-width figure (2-column) | 2400 x 1200 px (300 DPI at 8" wide) | JPG or PNG |
| Half-width figure (1-column) | 1200 x 1200 px | JPG or PNG |
| Qualitative strip (4-frame) | 4800 x 800 px (4 x 1200 wide) | PNG |
| SAM3 annotated overlay | Native camera resolution | PNG (alpha) |

### Video

| Purpose | Resolution | FPS | Codec | Bitrate |
|---------|-----------|-----|-------|---------|
| Supplementary video | 1920 x 1080 | 30 | H.264 | >= 8 Mbps |
| Per-trial recording | 1280 x 720 | 30 | H.264 | >= 4 Mbps |
| Tiled multi-view | 2560 x 720 (side-by-side) or 1920 x 1080 (2x2 grid) | 30 | H.264 | >= 8 Mbps |

## 4. Per-Trial Media Checklist

Every publishable trial should produce:

- [ ] **Hero still** -- single best frame, mid-task, showing robot + objects + workspace
- [ ] **Overhead still** -- birdview at task completion (success or characterized failure)
- [ ] **Success video** -- full trial from start to completion, single best camera angle
- [ ] **Tiled video** -- all camera views synchronized, side-by-side or 2x2
- [ ] **SAM3 annotated frame** -- detection overlay showing masks + labels + confidence + 3D position
- [ ] **BT plan screenshot** -- the YAML behavior tree as generated by Gemini (text or rendered)

For bimanual tasks, additionally:

- [ ] **Handoff close-up** -- zoomed frame at the moment of object transfer between arms
- [ ] **Parallel execution frame** -- both arms in motion simultaneously
- [ ] **Sync barrier frame** -- both arms paused at barrier, about to resume

## 9. Camera System Reference (for hardware section writing)

### UR10e / FR3 single-arm camera setup

| Camera | Model | Mount | Resolution | Depth | Role |
|--------|-------|-------|-----------|-------|------|
| Sideview | Azure Kinect DK | Fixed tripod/shelf, ~45 deg angle | 1080P color, 512x512 depth | WFOV_2X2BINNED (120 deg, 0.25-2.88m) | Primary localization |
| Birdview | Azure Kinect DK | Overhead mount | 1080P color, 512x512 depth | WFOV_2X2BINNED | Secondary localization, occlusion handling |
| Wrist | Intel RealSense D435I | 3D-printed bracket on EE | 640x480 | Stereo IR, 0.2-10m | Close-range verification, egocentric view |

Notes:
- Kinects are high-bandwidth USB3; opened sequentially with 3s stagger to avoid contention
- Camera-to-robot calibration: 6-point SVD, 3-8mm reprojection error
- Wrist extrinsic: computed dynamically from robot FK via known tool offset
- `kinect_use_hw_sync: false` (currently; master MCU locked on FR3 rig)

### Bimanual Franka camera setup

| Camera | Model | Mount | Resolution | Depth | Role |
|--------|-------|-------|-----------|-------|------|
| External | ZED Mini (ZED M) | Center tripod between arms | 1280x720 | Stereoscopic, NEURAL mode | Primary localization (global view) |
| Wrist Left | Intel RealSense D435I | Left arm EE bracket | 640x480 | Stereo IR | Left arm egocentric |
| Wrist Right | Intel RealSense D435I | Right arm EE bracket | 640x480 | Stereo IR | Right arm egocentric |

Notes:
- No Azure Kinects on bimanual rig
- ZED Mini provides stereoscopic depth (not monocular DA3)
- View fusion: external supplies primary localization; wrist views refine per-arm grasping
- Camera registry replaces hardcoded sideview/birdview/wrist slots

### SSG48 Grippers (bimanual only)

The SSG48 is a parallel-jaw gripper used on the bimanual Franka rig. It
replaces both the Franka Hand and the Dynamixel ALOHA jaws. SSG48s are
managed entirely in Python (`spark_real/robots/bimanual_franka/ssg48_gripper.py`),
independent of the Bamboo C++ control node (which runs with `-g none`).

- Width range: 0-90mm
- Default force: 15N (tunable per-skill)
- Communication: via dedicated interface (USB), not through FCI

## 10. Composite / Overlay Figures (CRITICAL for paper)

These figures demonstrate robustness to variation and are high-priority for reviewers.

### 10a. Object Position Overlay (per task)

For each task, capture **10 overhead shots** of the scene before the robot acts,
each with a different random object placement. Then composite them:

**How to capture:**
1. Set up the overhead camera (Azure Kinect birdview or ZED Mini)
2. Randomize object positions 10 times, take a photo each time
3. Name: `{embodiment}_{task}_overhead_placement_{01-10}.jpg`

**How to composite (I will do this in matplotlib):**
- Base image: one clean overhead frame
- Overlay: translucent (alpha=0.3) copies of the target object from each placement
- Color by trial outcome if available (green=success, red=fail)
- Result shows the distribution of tested positions at a glance

Priority tasks for this figure:
- [ ] `ur10e_sweep_overhead_placement_{01-10}.jpg` (screws/nails varied)
- [ ] `ur10e_silverware_overhead_placement_{01-10}.jpg` (varied utensils)
- [ ] `fr3_pour_overhead_placement_{01-10}.jpg` (kettle/mug varied positions)
- [ ] `bimanual_set_table_overhead_placement_{01-10}.jpg` (utensils varied)

## 11. Lighting and Background

For consistency across all media:

- **Lighting**: Overhead fluorescent lab lighting, supplemented by task lamp if needed for close-ups. Avoid harsh shadows on objects.
- **Background**: Keep workspace clean. Remove cables, tools, personal items from frame.
- **Table surface**: Use the standard lab foam/mat surface. Consistent color across trials.
- **Object arrangement**: Place objects in the starting configuration before each trial photo. Reset between trials.
- **White balance**: Lock camera white balance if possible to maintain color consistency across sessions.
